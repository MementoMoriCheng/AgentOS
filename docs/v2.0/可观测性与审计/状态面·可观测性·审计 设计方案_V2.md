# 状态面 · 可观测性 · 审计 设计方案（第二版）

> **版本**：v2.0
> **日期**：2026-07-02
> **定位**：两个微服务（**状态面** + **可观测性**）的职责边界、接口设计、契约协商
> **版本说明**：相对第一版（v3.1，含系统侧规划，已归档）的核心变更见下。
>
> **v2.0 变更（相对第一版）**：
> - **完全去掉系统侧可观测性**（Prometheus / Grafana / ELK / Jaeger / 告警等规划全部移除，不再涉及）
> - **状态面与可观测性拆为两个独立微服务**
> - **审计改为 MQ 消费**：状态面消费 `audit.{tenant}` Topic 物化到 `audit_log`（不再直写）
> - **消息总线、采纳追踪、记忆库全部归入可观测性微服务**
> - **状态面新增恢复接口**，返回完整恢复包（checkpoint + 事件 + token + adoption）
> - 文档聚焦**两个微服务自身**的职责与接口设计，不再作为跨模块全景文档

### 0.2 数据管道

```text
管道 ① 热路径（Agent 运行时，非可观测读源）
```

## 一、状态面微服务

### 1.1 定位

状态面是 CQRS **冷路径执行者**。它消费消息总线上所有 Topic 的事件，幂等物化到结构化 DB，并对外提供 Agent 恢复接口。

**不做的事**：

| 不做 | 谁来做 |
| --- | --- |
| 不写缓存数据库热状态 | Agent 引擎经 StateInterface SDK 直写（热路径） |
| 不做原语执行（Action / Observation） | Agent ↔ 沙箱的 WebSocket 通道 |
| 不提供可观测性查询 API | 可观测性微服务 |
| 不参与故障恢复过程本身 | 控制面执行恢复；状态面只提供数据 |

### 1.2 能力一：消费所有 MQ → 持久化到 DB

#### Topic 与物化表对应关系

| Topic | 消费组 | 物化目标表 | event_type | 用途 |
| --- | --- | --- | --- | --- |
| `agent_events.{tenant}.{session}` | sync-cg | `agent_run_event`、`react_checkpoint` | `AgentStarted` / `ActionDispatched` / `ObservationReturned` / `CheckpointSaved` / `AgentFinished` / `ErrorOccurred` | 运行追踪、恢复 |
| `sandbox_lifecycle.{tenant}` | sync-cg | `sandbox_lifecycle`（目标新增） | `SandboxCreated` / `SandboxHeartbeat` / `SandboxIdle` / `SandboxTimeout` / `SandboxDestroyed` | 沙箱生命周期 |
| `cost_events.{tenant}` | cost-cg | `token_usage` | `LLMCalled` | 成本计量 |
| `audit.{tenant}` | audit-cg | `audit_log` | 见 §3.3 action 枚举 | 审计台账 |
| `quality_events.{tenant}` | quality-cg | 质量分表（规划） | `VerificationFailed` 等 | 质量归档 |

> **现网契约类**：`MessageBusTopics`（Topic 命名）、`MessageBusEventTypes`（event_type 枚举）、`AuditTopics`（审计 Topic）——均在 `libs/gnex-contracts`。

#### 物化原则

1. **先物化、再标记幂等、最后 ack**——顺序错误会导致丢消息
2. **所有写入必须 upsert 幂等**（`ON CONFLICT DO UPDATE` / 唯一约束 `DO NOTHING`）
3. **CheckpointSaved 立即刷盘**——不等批次，避免崩溃窗口丢快照
4. **不写缓存 DB**——缓存库由 Agent 引擎热路径直写

#### 幂等去重

| Topic 频率 | 去重方式 | TTL |
| --- | --- | --- |
| 高频（agent_events、sandbox_lifecycle） | 缓存库 Set（`SISMEMBER` / `SADD`） | 24h / 6h |
| 低频（cost_events、quality_events） | DB 唯一索引（`ON CONFLICT (msg_id) DO NOTHING`） | — |
| 审计（audit.{tenant}） | 缓存库 Set + DB 副本 | 1h |

#### 消费循环与可靠性

```text
循环:
  1. consumeBatch(topic, consumerGroup, maxMessages, pollTimeout)
  2. 对每条 msg:
     a. 幂等检查(msgId) → 命中则 ack 跳过（仍须 ack，否则总线重投）
     b. 物化（写结构化库）
     c. 写幂等标记（在 ack 之前）
     d. ack（仅物化成功才确认；不调 ack → 总线按策略重投）
```

**异常处理**：

| 失败类型 | 表现 | 状态面应对 |
| --- | --- | --- |
| 连接级 | broker 不可达，consume 抛异常 | 捕获后重连；重连期间不物化、不 ack |
| 业务级 | DB 写失败、超时 | 不调 ack → 总线重试 → 超限进死信队列 |
| 正常空轮询 | pollTimeout 到，返回空列表 | 继续 poll（非异常） |

**顺序与隔离**：

- 同 session 的 `agent_events` 按 orderKey（`{tenant_id}:{session_id}`）保序消费，避免 step 乱序物化。
- audit-cg 与 sync-cg 分属不同消费组 / 不同 queue，审计慢消费不得拖累 checkpoint 物化。
- 总线 at-least-once 投递；状态面通过幂等去重实现 effectively-once 语义。

### 1.3 能力二：Agent 恢复接口（预留）

当 Agent 引擎需要恢复某个 session 的执行状态时，调用状态面提供的恢复接口，获取**完整恢复包**。

#### 接口定义

```text
GET /api/state-plane/sessions/{sessionId}/restore
```

| 参数 | 说明 |
| --- | --- |
| `sessionId` | 会话 ID（路径参数） |

#### 响应：恢复包（RestorePackage）

```json
{
  "session_id": 12345,
  "checkpoint": {
    "run_id": "run_abc",
    "next_turn_index": 5,
    "max_turns": 20,
    "total_token_usage": 15000,
    "effective_model": "claude-sonnet-4-20250514",
    "messages_json": "[...]",
    "status": "RESUMABLE"
  },
  "events": [
    {
      "id": 101,
      "run_id": "run_abc",
      "event_type": "model_call",
      "event_name": "MODEL_ROUTE",
      "seq": 1,
      "duration_ms": 3200,
      "token_count": 500,
      "parent_event_id": null,
      "model_call_id": "mc_001"
    }
  ],
  "token_usage": [
    {
      "model": "claude-sonnet-4-20250514",
      "input_tokens": 1200,
      "output_tokens": 800,
      "cost_usd": 0.012
    }
  ],
  "output_adoption": [
    {
      "message_id": 201,
      "status": "ADOPTED",
      "feedback": ""
    }
  ]
}
```

#### 恢复包内容

| 字段 | 来源表 | 用途 |
| --- | --- | --- |
| `checkpoint` | `react_checkpoint` | 权威快照基线（messages + step） |
| `events` | `agent_run_event`（按 `run_id` 过滤，`seq` 排序） | 事件时间线，补齐 checkpoint 之后的增量 |
| `token_usage` | `token_usage`（按 `session_id` 过滤） | 累计 Token / 成本 |
| `output_adoption` | `output_adoption`（按 `session_id` 过滤） | 已采纳 / 忽略的消息记录 |

> **恢复公式**：
>
> ```text
> 最终状态 = DB checkpoint（基线）+ MQ 增量事件（补齐）+ 缓存 DB 热状态（可选加速）
> ```
>
> 状态面提供结构化库 checkpoint + 事件流的数据源；缓存库热状态由 Agent 引擎自行读取（可选加速）。

#### 契约接口（Interface）

```java
public interface StateRestoreInterface {

    /** 获取指定 session 的完整恢复包。 */
    RestorePackage restore(Long sessionId);
}
```

> 此接口为**预留接口**，当前由 `ReActCheckpointQueryInterface`（现网类名 `ReActCheckpointQueryPort`，迁移时更名）过渡，仅返回 checkpoint。目标态由状态面微服务实现完整恢复包。

## 二、可观测性微服务

### 2.1 定位

可观测性微服务**只读**状态面物化的 DB，经 Query Interface 统一对外提供查询 API，供观测中心前端展示。**不单独写数据**，不建独立 Projector。

### 2.2 Query Interface 逻辑分组

| Interface | 职责 | 现网实现类（迁移参考） |
| --- | --- | --- |
| `OperationsQueryInterface` | 运营指标聚合 | `OperationsMetricsPort`（`OperationsMetricsPortAdapter`） |
| `RunTraceQueryInterface` | Run 事件树、决策、Provider Trace | `AgentRunEventQueryPort`（`AgentRunEventQueryPortAdapter`） |
| `AdoptionQueryInterface` | 采纳统计 | `OutputAdoptionPort`（`OutputAdoptionPortAdapter`） |

### 2.8 关联键

```text
tenant_id → project_id → session_id → run_id → tool_call_id / request_id
         └─ trace_id（MQ Envelope 携带，业务关联用）
```

每条 MQ Envelope、每条物化记录均携带 `trace_id`（从 MQ 消息体取值），供可观测性 API 跨层拼接。`run_id` 是观测中心 Run Trace 主键；`trace_id` 用于关联同一请求的多个事件。

> **注**：本期不涉及 OTel / Jaeger / MDC 等系统链路追踪。`trace_id` 仅作为业务关联键，从 MQ Envelope 传递到 DB 记录。

## 三、审计日志

### 3.1 写入路径：MQ 消费

```text
业务发生点（登录、工具批准、MCP 变更…）
  → publish MQ（audit.{tenant} Topic）
  → 状态面微服务（audit-cg 消费组）消费
  → 幂等物化到 audit_log 表
  → 可观测性微服务 AuditLogQueryInterface 查询
  → GET /api/audit、/api/audit/export
```

**与第一版的差异**：第一版目标态为「直写 audit_log」；经开发小组讨论，改为统一走 MQ，由状态面消费物化，与 agent_events / cost_events 等管道一致。

**审计消息体**（BusEventMessage）：

```json
{
  "tenantId": "t_001",
  "projectId": "1",
  "sessionId": "sess_xyz",
  "eventType": "TOOL_APPROVE",
  "topic": "audit.t_001",
  "requestId": "req_001",
  "traceId": "trace_def",
  "payload": "{\"user_id\":1,\"action\":\"TOOL_APPROVE\",\"resource_type\":\"TOOL\",\"resource_id\":\"shell_exec\",\"detail\":\"approved\",\"ip_address\":\"10.0.0.1\"}",
  "attributes": {},
  "createdAt": "2026-07-02T12:00:00Z"
}
```

状态面消费时从 `payload` JSON 中解析 `user_id`、`action`、`resource_type`、`resource_id`、`detail`、`ip_address` 等字段，物化到 `audit_log` 表。

### 3.2 audit_log 表结构（现网 + 目标态扩展）

**现网表**（`V4__user_and_audit.sql`）：

```sql
CREATE TABLE IF NOT EXISTS audit_log (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id       INTEGER,
    action        TEXT    NOT NULL,
    resource_type TEXT,
    resource_id   TEXT,
    detail        TEXT,
    ip_address    TEXT,
    created_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**目标态扩展字段**（需迁移）：

| 新增字段 | 类型 | 说明 |
| --- | --- | --- |
| `tenant_id` | TEXT | 租户隔离（`NOT NULL DEFAULT 'default'`） |
| `project_id` | BIGINT | 项目隔离 |
| `session_id` | BIGINT | 会话关联 |
| `run_id` | TEXT | Run 关联 |
| `msg_id` | TEXT | MQ 消息 ID（幂等去重，唯一约束） |

### 3.3 audit_log.action 枚举

| 分组 | 值 | 触发组件 |
| --- | --- | --- |
| 身份 | `LOGIN`, `LOGIN_FAILED`, `REGISTER`, `LOGOUT` | 认证服务 |
| 工具 / HITL | `TOOL_CALL`, `TOOL_APPROVE`, `TOOL_REJECT`, `TOOL_DENY`, `TOOL_FAIL`, `TOOL_CANCEL` | Agent 引擎、确认流 |
| 沙箱 | `SANDBOX_DENY` | 沙箱调度器 |
| 管理 | `CUSTOM_TOOL_REGISTER`, `CUSTOM_TOOL_UNREGISTER`, `MCP_CONNECT`, `MCP_DISCONNECT`, `MCP_RECONNECT` | 运营管理服务 |
| 交互 | `USER_QUESTION_ANSWER`, `CHAT`, `EXECUTE`, `CANCEL`, `INSTALL` | Agent / Chat |

> 现网契约类：`ToolAuditActions`、`ManagementAuditActions`（`libs/gnex-contracts`）。新增 action 须：更新契约常量类 + 前端审计筛选字典 + 本表。

### 3.4 API 目录：审计（`/audit`）

| API | 方法 | 查询参数 | 响应要点 |
| --- | --- | --- | --- |
| `/api/audit` | GET | `userId`, `action`, `resourceType`, `runId`, `sessionId`, `from`, `to`, `limit` | `AuditLog[]` |
| `/api/audit/export` | GET | 同上 | CSV blob |

**权限**：ADMIN 全量；DEVELOPER 本项目。支持 `run_id` / `session_id` 深链跳转运行追踪。

### 3.5 审计特殊可靠性要求

- audit.{tenant} Topic 进死信队列必须 **P1 告警 + 及时 requeue**——死信默认保留 72h，过期即丢，而审计要 **90 天合规留存**
- audit-cg 消费组与 sync-cg 分属不同消费组 / 不同 queue，避免审计慢查询拖累 checkpoint 物化

### 5.1 MQ Envelope（统一消息体）

现网契约类：`BusEventMessage`（`libs/gnex-contracts`）。

```json
{
  "tenantId": "t_001",
  "projectId": "1",
  "sessionId": "sess_xyz",
  "eventType": "LLMCalled",
  "topic": "agent_events.t_001.sess_xyz",
  "requestId": "req_001",
  "traceId": "trace_def",
  "payload": "{ }",
  "attributes": { },
  "createdAt": "2026-07-02T12:00:00Z"
}
```

**责任划分**：

| 角色 | 职责 |
| --- | --- |
| **生产者**（Agent 引擎、模型网关、沙箱调度器等） | 保证 `eventType` + `payload` schema 正确；publish 到正确 Topic |
| **状态面微服务** | 消费 → 幂等物化 → ack |
| **消息总线** | 保证 at-least-once 投递、重试、死信 |
| **可观测性微服务** | 只读 DB，不参与生产 / 消费 |

### 5.4 两个微服务的边界

| 维度 | 状态面微服务 | 可观测性微服务 |
| --- | --- | --- |
| **写入** | 消费 MQ → 物化多表 | 不写 |
| **读取** | 恢复接口读自身物化表 | Query Interface 读状态面物化表 |
| **MQ 角色** | 消费者（consume） | 不参与业务 Topic 消费；消息总线 Tab 只读查 broker（BFF） |
| **目的** | 持久化 + 恢复 | 展示 + 排障 |
| **丢失容忍** | MQ 不可丢（恢复依赖） | 秒级投影延迟可接受 |

## 六、现网差距与迁移

| 能力 | 现网 | 目标态 | 迁移备注 |
| --- | --- | --- | --- |
| Run 事件落库 | `AgentRunEventService` 同步直写 | 状态面消费 MQ 物化 | 双写过渡期 |
| Checkpoint | `ReActCheckpointService` JDBC 直写 | 状态面消费 `CheckpointSaved` 物化 | 表名 `react_checkpoint` 保留 |
| Token | 直写 `token_usage` | 状态面消费 `cost_events` 物化 | 逐步统一 |
| 审计 | MQ `audit.{tenant}` → `AuditLogConsumerScheduler` 消费 | 状态面 audit-cg 消费物化 | 消费者迁移到状态面微服务 |
| 恢复接口 | `ReActCheckpointQueryPort`（仅 checkpoint） | `StateRestoreInterface`（完整恢复包） | 新增接口，现网类迁移时更名 |
| Query Interface | 分散在 agent-service / platform-service（现网 `*Port*` 命名） | 全部归入可观测性微服务（统一 `*Interface` 命名） | 逻辑归属变更，物理 API 可不变 |
| 状态面微服务 | 不存在 | 独立微服务 | 新建 |
| 可观测性微服务 | 不存在 | 独立微服务 | 迁移现有 Controller / Adapter |
| `audit_log` 表 | 缺 `tenant_id` / `project_id` / `session_id` / `run_id` / `msg_id` | 扩展字段 + 迁移 | 新增迁移脚本 |
| `token_usage` 表 | 缺 `tenant_id` / `project_id` / `run_id` / `route_tier` | 扩展字段 | 新增迁移脚本 |
| 消息总线传输 | 自研 database + Redis Streams | 依赖总线 Phase3（RocketMQ） | 状态面消费能力依赖总线就绪 |
| 消息总线观测 | `/api/message-bus/*` + `agent_message_bus` | `/api/observability/bus/*` BFF + `BusAdminInterface` | legacy 路径 deprecated；写操作归 bus-admin |

## 七、设计脉络总结

1. **两个微服务职责清晰**：状态面写（消费 MQ → 物化 DB + 恢复接口），可观测性读（Query Interface → 观测中心）。
2. **审计统一走 MQ**：不再直写，由状态面 audit-cg 消费 `audit.{tenant}` 物化到 `audit_log`，与其他管道一致。
3. **所有 Topic 与物化表一一对应**：`agent_events` → `agent_run_event` / `react_checkpoint`；`cost_events` → `token_usage`；`audit.{tenant}` → `audit_log`；`sandbox_lifecycle` → `sandbox_lifecycle`。
4. **恢复接口返回完整包**：checkpoint + 事件 + token + adoption，供 Agent 引擎恢复使用。
5. **可观测性覆盖观测中心全部页面**：运行指标、运行追踪、决策归因、采纳追踪、记忆库、消息总线（只读 BFF）、审计、沙箱。
6. **系统侧可观测性本期不涉及**：Prometheus / Grafana / ELK / Jaeger / 告警等不在本文范围。

**哲学不变**：状态可重建、行为可回放、故障可恢复、人可追责。
